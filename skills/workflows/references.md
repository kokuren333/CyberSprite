# references — 参照を手に入れる、測る、記録する

**使う場面**: 既存のゲームのスプライトなど、他人の絵を参照して、粒度や作法を測りたいとき。どの手順書（`turnaround-parts`、`silhouette-first` など）の段 0 からも使う。

規律の正本は `docs/SPEC.md` §3.6。このページはその手順である。

## 1. 思想と原則

- **参照は測るためのものであって、写すためのものではない。** 成果物は、参照を踏まえたオリジナルである。
- 参照の画像は、リポジトリにも、プロジェクトの `source/` にも入れない。プロジェクトは作例として公開されうる。制作中のプロジェクトから見えるようにするときは、§2.2 の手動の取り込み（`register_reference`）だけを使う。画像は git の管理外の `.cybersprite/references/` に置かれ、`source/manifest.json` には ID・ハッシュ・権利メモだけが残る。
- 追跡する文書に書いてよいのは、統計値と自分の言葉での所見まで。作品の題名や画像は書かない。

## 2. 手順

### 2.1 置き場所（参照ライブラリ）

```text
_private/refs-library/            （またはリポジトリの外の同じ形のディレクトリ）
  <機種>/<作品>/<id>_<slug>.png
  manifest.jsonl                  1 行 1 枚: 出典の URL、寸法、色数、sha256、取得日
```

- `_private/` は git の管理外である（`docs/SPEC.md` §3.4）。
- 同じ ID の画像は 1 枚だけ置く（取り直さない）。

### 2.2 手に入れる、取り込む

**標準: 人がブラウザなどで見て保存した画像を、手動で取り込む。** 取得の道具は使わない。

1. **見つけて保存する（人）。** 利用者（または利用者に頼まれた人）が資料を自分の目で探し、必要な分だけ保存する。使い回すものは、上の形でライブラリに置き、`manifest.jsonl` に 1 行足す。
2. **プロジェクトに取り込む（手動）。** 制作中のプロジェクトから参照を見たいときは、次のどれかで添付する。3 つとも同じ Op（`register_reference`）を通り、同じ一覧に載る。
   - **GUI**: 右のパネルの「ソース」タブ →「参照画像を添付」。画像を選ぶかドロップし、権利メモを書いて「添付」。来歴には `placed_by: human-gui` が残る。
   - **CLI**: `csp -p hero.csprite source reference <保存した画像> --rights-note "市販ゲームのスプライト。計測のみ"`。人が打つときは既定の `human-cli`、エージェントが CLI で添付するときは `--placed-by agent` を付ける。
   - **エージェント（MCP）**: `register_reference` に `file`（MCP の root の中のパス）と `rights_note` を渡す。`placed_by` は常に `agent` になる。
3. **エージェントが受け取る。** `list_sources`（CLI: `source list`）で `use: "reference"` の項目を見る。`files` のパスを開いて計測する（§2.3）。GUI で人が添付したものも、ここに `human-gui` で出る。

規則:

- まずライブラリと `list_sources` を見る。あるものは取り直さない。同じ画像を取り込んでも、`duplicate: true` で同じ ID が返るだけである。
- 必要な分だけ、少量だけ。一括で集めない（ミラーしない）。
- 資料サイトの利用規約に従う。自動の取得を断っているサイトから、道具を使って取ってこない。
- **エージェントは、資料サイトから自分で取得しない。** 足りないときは、何が要るか（機種や世代、題材、向き、動作）を利用者に具体的に頼み、報告にそう書く。
- 権利メモは必須。誰の絵で、どう使ってよいか（例「市販ゲームのスプライト。計測のみ」「自分で撮った写真」）を書く。**題名、ファイル名、URL は書かない**（`source/manifest.json` はプロジェクトとともに公開されうる）。出典の URL はライブラリの `manifest.jsonl` にだけ書く。
- 上限は 1 枚 5 MiB。大きいときは、測りたい部分を切り出して PNG で保存し直す。
- 添付した参照は `validate` がハッシュを照合する。消えたり書き換わったりすると `Q-SRC-05`（warning）が出る。

### 2.3 測る

してよいのは、**計測と、自分の言葉での所見**だけ。

- 測るもの（例）: 外接矩形、不透明の色数、占有率、輪郭からの深さ、輪郭に占める最も暗い色の割合、素材ごとの陰影の段数、ディザの有無、部品の寸法比（頭の幅に対する目の幅）、アニメーションのユニークなコマ数。
- 測り方: Pillow などで**読み取りだけ**を行う作業用スクリプトを、リポジトリの外か `_private/` の中に書く。結果は数値で残す。
- 全体の統計だけでなく、**顔の部品と影の形**も測る。80×80 の試作では、全体の統計だけを測って、顔と影を見落とした（`docs/REVIEW_1.md` §2.2 要因 6）。
- 少数の参照から測った値を、一般の規則に格上げしない。物差しとして使う。

### 2.4 してはならないこと

- なぞること。画素を書き写すこと（`draw_rows` に写すことも含む）。
- 1 つのスプライトのパレットを、そのまま使うこと。
- 既存のキャラクターに似せること。
- 参照の画像を `import_image` や `add_source` でプロジェクトに入れること。添付は `register_reference` だけで、参照のソースはキャンバスへの取り込みにも下絵にも使えない（使おうとするとエラーになる）。

### 2.5 imagegen に渡すもの

- 渡すのは**文章の指示と、測った数値**だけにする。参照の画像を画像入力として渡さない。出力が元の絵に近づく危険が上がるため（`docs/REVIEW_1.md` §3.5、§6 の 3）。
- 作品名、キャラクター名も渡さない。「〜風」は、測った特徴の言葉に置き換える（例「頭の幅の 3 分の 1 ほどの目」「素材ごとに 3 段の陰影」「色つきの輪郭」）。
- この方針は上流の推奨で、発注者はまだ決めていない。発注者が別の指示を出したら、それに従う。

### 2.6 並べて見る

- 参照を並べたレビューシートは、プロジェクトの `.cybersprite/previews/`（git の管理外）か `_private/` の中だけに置く。
- `e2e-tests/` や `examples/` など、追跡するディレクトリに写さない。制作記録にはパスだけを書く。

### 2.7 記録する

使うたびに `docs/reference/PROVENANCE_LOG.md` に 1 行書く。

```text
| 日付 | 参照者 | 資料 | 何の事実を得たか | 反映先 |
| <日付> | <参照者 / 作業名> | 参照ライブラリの <世代や機種> の市販スプライト <点数>（<種類の内訳>。`_private/refs-library/`、計測のみ） | <測った項目と値の範囲> | <反映先: 制作記録のパスなど> |
```

- 書くのは点数、種類、統計値まで。題名、ファイル名、URL、画像は書かない。
- プロジェクトや制作記録に残してよいのは、参照の ID（manifest の sha256 など）と計測値だけ。

## 3. 失敗チェックリスト

- [ ] 参照の画像を、プロジェクトの `source/`、`e2e-tests/`、`examples/` に置いていないか（添付は `register_reference` で `.cybersprite/references/` に入る）。
- [ ] 権利メモに、題名、ファイル名、URL を書いていないか。
- [ ] 参照の画素やパレットを、そのまま使っていないか。
- [ ] 参照の画像や作品名を、imagegen への指示に入れていないか。
- [ ] 参照ログに 1 行書いたか。題名や画像を書いていないか。
- [ ] 全体の統計だけを測って、顔の部品と影の形を見落としていないか。
- [ ] 参照を一括に集めていないか（必要な分だけ、ライブラリにあるものは取り直さない）。エージェントが自分で資料サイトから取ってきていないか。
