# tiles-first — タイルから（タイルセットとタイルで組む絵）

**使う場面**: タイルセット、タイルマップ、タイルの予算がある機種の背景やマップ。プラットフォームの `workflow` が `tiles-first` のとき。

## 1. 思想と原則

- 細部の要らない面（草、水、土、壁）は、エージェントが比較的得意である（発注者の申し送りの DM 知見 2。e2e-04 のタイルは実用の水準だった。`docs/REVIEW_1.md` §2.1）。
- 崩れやすいのは継ぎ目と繰り返しの目立ち方である。1 枚のタイルではなく、**並べた状態**で判断する。
- 機種にタイルの枚数や色表の制約があれば、先に決めて守る（M11 以降は検証が数える）。

## 2. 段と関門

| 段 | 担当 | すること | 関門 |
|---|---|---|---|
| 0 | Opus | タイルの大きさ、枚数の予算、パレット（色表）を決める。並べたい場面を 1 行で書く | |
| 1 | Opus | 基本のタイル（地面 1 種と継ぎ目）を作り、小さなマップに並べる | **(1) 設計**（色調と密度） |
| 2 | Opus | 継ぎ目、角、変化のタイルを足す。反転で使い回す | **(2) ブロッキング**（並べて継ぎ目が読めるか） |
| 3 | Opus | 細部と変化をつけ、重複を統合する | **(3) 仕上げ前** |
| 4 | Opus | 検証、書き出し（タイルセットとマップ）、書き出したファイルの確認 | |

- 関門の運用は [`turnaround-parts.md`](turnaround-parts.md) §2 と同じ。題材が小さく単純なら、(2) と (3) をまとめてよい。
- 原案の生成（Codex imagegen）で場面の雰囲気を先に決めてもよい（[`turnaround-parts.md`](turnaround-parts.md) §3.2）。

## 3. 手順

詳しい操作は [`tileset`](../tileset/SKILL.md)。関門で見せるのは、タイル一覧（`preview --tileset`）だけでなく、**並べたマップ**の ×1 と整数倍である。

```powershell
csp -p meadow.csprite preview --tileset TS1 --out review/g2_tiles.png
csp -p meadow.csprite preview --frame 0 --scale 1 --out review/g2_map_x1.png
csp -p meadow.csprite preview --frame 0 --scale 4 --grid --out review/g2_map_x4.png
```

## 4. 失敗チェックリスト

- [ ] 1 枚のタイルだけを見て、並べた状態を見ずに進めていないか。
- [ ] 同じタイルの繰り返しが、縞や格子として目立っていないか。
- [ ] タイルの予算と色表の制約を守っているか。
- [ ] 見た目の合格を自分で宣言していないか。判定は `pending` のままか。
