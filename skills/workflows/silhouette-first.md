# silhouette-first — シルエットから（極小で制約の厳しいスプライト）

**使う場面**: 16×16 以下で、色数がごく少ないもの（例: 3 色 ＋ 透明、8×8 のタイル単位）。携帯機の実機の制約に合わせたキャラクターや、マップ上の歩行キャラクターなど。プラットフォームの `workflow` が `silhouette-first` のとき。

## 1. 思想と原則

- 極小の制約では、「描く力」より「制約の下で設計する力」が要る。16×16・3 色では、エージェントの試作は顔が読めず、側面と背面が塊につぶれた（発注者の申し送りの DM 知見 1。`docs/REVIEW_1.md` §3.3.1）。
- **1 案が安いので、たくさん作って人間が選ぶ。** シルエットの段階で 8〜12 案を 1 枚に並べ、利用者に選んでもらう。これがいちばん効くと考えられている。
- 色の役割（輪郭、主色、陰影）を先に決め、守る。
- 道具が保証できるのは、制約を破らないことと、人間が早い段階で見て選べることまでである。手描きの水準に届く保証はない。

## 2. 段と関門

| 段 | 担当 | すること | 関門 |
|---|---|---|---|
| 0 | Opus | 制約（大きさ、色数、タイル、色表）を決める。色の役割を決める | |
| 1 | Opus | 1 色でシルエットだけを、8〜12 案作る。向きがあれば 4 方向を並べる | **(1) 設計**（案を選ぶ） |
| 2 | Opus | 2 色目で内側の切れ目（顔、腕、体の境）を入れる | **(2) ブロッキング** |
| 3 | Opus | 3 色目（と残りの色）を入れる。歩行などのコマを作る | **(3) 仕上げ前** |
| 4 | Opus | 検証、書き出し、書き出したファイルの確認 | |

- 原案の生成（Codex imagegen）は、使ってもよいが必須ではない。使うときは [`turnaround-parts.md`](turnaround-parts.md) §3.2 の呼び出し方と指示の書き方に従う。極小では、原画より、シルエットの案を多く並べるほうが効く。
- 関門の運用（対話できるとき、自律タスクのとき）は [`turnaround-parts.md`](turnaround-parts.md) §2 と同じ。

## 3. 手順

`csp` は `uv run --project <リポジトリ> csp`。

1. **制約を決める。** `new --platform`（M11 で追加。例 `dmg/sprite-16`）が使えればそれで作る。まだ無ければ、`new --size 16x16 --palette gray-4` などで作り、制約を制作記録に書く。
2. **案を並べる。** 案ごとにフレームを 1 枚使うと、`preview --frames all --layout grid --scale 1` と `--scale 4` で 1 枚に並べられる。
   ```powershell
   csp new idea.csprite --size 16x16 --palette gray-4
   csp -p idea.csprite op add_frame count=11
   # フレームごとに 1 色でシルエットを打つ（draw_rows の sym 形式が速い）
   csp -p idea.csprite preview --frames all --layout grid --scale 1 --out review/g1_x1.png
   csp -p idea.csprite preview --frames all --layout grid --scale 4 --out review/g1_x4.png
   ```
3. **4 方向を並べて見る。** 方向どうしの画素の違いが少ないと、向きが見分けにくい。並べたシートで確かめる。
4. **色を足す。** 2 色目で内側の切れ目、3 色目で陰影。色の役割を守っているか、明るさだけの版で見る（[`validate-export`](../validate-export/SKILL.md) §2.5）。
5. **×1 で読めるか**を、関門ごとに確かめる。拡大だけで判断しない。

## 4. 測る観察（照合用）

- 数えられるもの: 4 方向のコマどうしの画素の違い、色ごとの面積の割合、輪郭に占める最も暗い色の割合、ユニークなタイルの数。M11 以降は `metrics.platform` と `craft` に出る。**合否には使わない**（`docs/REVIEW_1.md` §3.3.1）。
- 小さい絵では、1 px がそのまま意味の単位になる。目は 1〜2 px で成立する。

## 5. 失敗チェックリスト

- [ ] シルエットの案を 1 つしか作らずに進めていないか。
- [ ] 色の役割（輪郭、主色、陰影）が、途中で崩れていないか。
- [ ] 側面と背面が塊につぶれていないか。4 方向を並べて見たか。
- [ ] 拡大だけを見て、×1 で読めるかを確かめずに進めていないか。
- [ ] 見た目の合格を自分で宣言していないか。判定は `pending` のままか。
