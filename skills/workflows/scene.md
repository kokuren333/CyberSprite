# scene — 場面（画面全体の一枚絵、背景）

**使う場面**: 画面と同じ大きさの背景、タイトル画面、一枚絵の場面（例: 320×180 の背景、灯台のある海辺）。タイルの制約が無いもの。タイルで組むなら [`tiles-first.md`](tiles-first.md)。プラットフォームの `workflow` が `scene` のとき。

## 1. 思想と原則

- 細部の情報が要らない背景は、エージェントが比較的うまく描ける（発注者の申し送りの DM 知見 2）。崩れやすいのは、構図と、手前に置く人物や小物の細部である。
- 面積が大きいので、**大きな形 → 明暗の配置 → 色 → 細部**の順に、人間が途中で見られるように進める。
- 場面の中のキャラクターや小物が大きければ、それだけは [`turnaround-parts.md`](turnaround-parts.md) か [`direct.md`](direct.md) で別に作り、レイヤーで重ねる。

## 2. 段と関門

| 段 | 担当 | すること | 関門 |
|---|---|---|---|
| 0 | Opus | 画面の大きさ、パレット、時間帯や光源を決める | |
| 1 | Codex（任意） | 場面の原画（構図と色調の案）を生成する。来歴つきで登録する | **(1) 設計**（構図と色調） |
| 2 | Opus | 大きな形と明暗の配置（ブロッキング）。レイヤーを奥行きで分ける | **(2) ブロッキング** |
| 3 | Opus | 色、質感、細部 | **(3) 仕上げ前** |
| 4 | Opus | 検証、書き出し、書き出したファイルの確認 | |

- 原画の生成と登録は [`turnaround-parts.md`](turnaround-parts.md) §3.2（三面図の代わりに、構図の案を 2〜3 枚頼む）。
- 原画を変換パイプラインで取り込んで下書きにする道もある（写真・イラスト向けの方式。[`turnaround-parts.md`](turnaround-parts.md) §3.4 道 B）。
- 関門の運用は [`turnaround-parts.md`](turnaround-parts.md) §2 と同じ。

## 3. 手順

- 大きなキャンバスでは、1 回の変更に時間がかかることがある（`docs/PERFORMANCE.md`）。1 トランザクションにまとめる意図の大きさを、少し大きめにしてよい。
- 関門のシートには、×1 の実寸（画面の大きさそのもの）を必ず入れる。拡大した部分は、切り出し（`--rect`、M12 で追加）で見る。
- 明暗の配置は、明るさだけの版で確かめる（[`validate-export`](../validate-export/SKILL.md) §2.5）。

## 4. 失敗チェックリスト

- [ ] 細部から描き始めて、構図が決まる前に時間を使っていないか。
- [ ] ×1 の実寸を見ずに、拡大だけで判断していないか。
- [ ] 場面の中の大きなキャラクターを、背景と同じ流れで描いていないか。
- [ ] 見た目の合格を自分で宣言していないか。判定は `pending` のままか。
