# skills/

エージェント（Claude Code、Codex）向けの制作手順書の置き場所。**手順書はまだない。** ツールが動くようになった後、M10 で書く（`docs/SPEC.md` §16.7）。

## 予定している手順書

| ディレクトリ | 内容 |
|---|---|
| `draw-sprite/` | 新規スプライトの作画。パレットを先に決める、シルエットから描く、プレビューを見て直す、検証する |
| `animate/` | フレームの追加、リンクセルの使いどころ、タグ、オニオンスキンでの確認、表示時間 |
| `tileset/` | タイルセットとタイルマップ。継ぎ目の確認、タイルの重複の統合 |
| `import-convert/` | 生成画像や既存画像の取り込み。プリセットの選び方、段階画像の読み方、関門に落ちたときの対処、来歴の書き方 |
| `validate-export/` | 検証の読み方、警告の扱い、書き出しと自己検査、完了条件 |

## 書き方の規則

各手順書は `skills/<名前>/SKILL.md` に、次の 3 部構成で書く。

1. **思想と原則** — なぜそうするのか。数行。
2. **手順** — 使うツールと順序。具体的な呼び出し例を付ける。
3. **失敗チェックリスト** — 実際に起きた失敗から足していく。

**ハーネスは、あえて緩くする。** 手順書が定めるのは、品質保証（事前の確認、事後の確認、検証のループ）と再現性である。何をどう描くかを縛る禁止事項や固定の雛形は置かない。

方向性を決める場面（新しいアセットの画風など）では、3 案ほどを作って利用者に選んでもらうことを勧める。

情報の優先順位は、指示 ＞ 仕様書 ＞ 原則 ＞ 過去事例（`AGENTS.md` §1）。
