## 3. GitHub リポジトリ: 未作成（止まった地点と理由）

**ローカルの git までは完成している。** GitHub 側は次の理由で作成できなかった。

| 試したこと | 結果 |
|---|---|
| `gh --version` | `gh` が見つからない（PATH にも、標準のインストール先にもない） |
| 環境変数 `GH_TOKEN` / `GITHUB_TOKEN` | どちらも未設定 |
| `git ls-remote https://github.com/kokuren333/CyberSprite.git` | 失敗（リポジトリが存在しない） |

- git 自体は、`user.name = kokuren333` が設定済みで、Git Credential Manager に `kokuren333` のアカウントが登録されている。**リポジトリさえ作れば、push は追加のログインなしで通る見込みである。**
- 資格情報マネージャーに保存されたトークンを取り出して GitHub の API を直接呼ぶ方法は、採らなかった。保存された資格情報を想定外の用途に使うことになるため、発注者の判断を仰ぐべきだと考えた。
- `gh` を導入しても、初回の認証（ブラウザかデバイスコード）は対話操作が必要で、ヘッドレス実行では完了できない。
- ローカルのリモート設定 `origin = https://github.com/kokuren333/CyberSprite.git` は済ませてある。

**再開の手順（どちらか）**

```
# A. ブラウザで github.com/new から「CyberSprite」を空のまま作成（README や LICENSE を追加しない）してから
git -C "<repo>" push -u origin main

# B. gh を入れて認証してから
winget install GitHub.cli
gh auth login
gh repo create kokuren333/CyberSprite --private --source "<repo>" --remote origin --push
```

公開範囲について: 現時点のリポジトリは仕様書だけでコードがない。**まず非公開（private）で作り、公開への切り替えは発注者が判断する**ことを勧める（仕様の M0 にもそう書いた）。

## 7. 主な判断（詳細は `docs/SPEC.md` 付録 E と `docs/REQUIREMENTS_NOTES.md` §3）

| 判断 | 要点 |
|---|---|
| 常にインデックスカラー（D-03） | RGBA / グレースケールの**編集モードは持たない。** RGBA は取り込み時に量子化し、RGBA での書き出しは常にできる |
| 正本の形（D-01、D-02、D-10） | ディレクトリ型のプロジェクト。ピクセルは行ごとの 16 進文字列（圧縮なし）。セルを正規化して「同じ絵は同じ JSON」にする |
| Op レジストリ（D-07） | 変更経路は 1 つ。CLI、MCP、GUI はそこから生成する。Op 名 = MCP ツール名 |
| トランザクション（D-08、D-09、D-21） | 原子的。構造の違反は破棄、品質の違反は報告だけ。取り消しは新しいリビジョン。冪等性クラスと冪等キー |
| 決定性の定義（D-11） | ピクセルと正本は全環境で同一。ファイルのバイト同一は、JSON・GIF・無圧縮 PNG で全環境、zlib 圧縮の PNG は同じ実行環境指紋のもとで保証 |
| 整数だけの計算（D-12、D-13、D-14） | 合成、色距離（固定小数点 Oklab）、量子化（整数メディアンカットと k-means）をすべて整数で定義 |
| 依存を絞る（D-15、D-16、D-17） | OpenCV / scikit-image / SciPy を使わない。**PixelOE は任意の extra**（PyTorch が重く、結果が環境に依存するため）。`.aseprite` は `aseprite` パッケージをアダプタ越しに使い、だめなら自前実装 |
| GUI（D-18、D-19） | Web 技術（TypeScript + React）とローカルサーバ。Qt は LGPL のため不採用。合成はコアが行う |
| MCP（D-20、D-31） | ステートレス、全ツールが `project` を明示、許可ディレクトリ内だけ読み書き、任意コード実行のツールなし |
| v1 の線引き（§7） | v1 は「エージェントの制作ループに必要なもの」「後から足すと互換が壊れるもの」「`.aseprite` の往復に必要なもの」。GUI は「見る・確かめる・軽く直す」まで。ブレンドモードの描画、任意角度の変形、タイルマップの GUI 編集、Lua 互換などは v1.x 以降か対象外 |

## 9. 実装時に揉めそうな論点

| # | 論点 | 仕様での扱い | 揉める理由 |
|---|---|---|---|
| 1 | **RGBA 編集モードがない**ことと「Aseprite の完全上位互換」 | 対象外（§1.3、§7.2） | 発注方針の「インデックスが正本」を優先した結果だが、「完全上位互換」の言葉どおりではない。**発注者の了承がほしい** |
| 2 | **「バイト同一」の定義** | 2 水準に分けた（§6.6） | ブリーフは「バイト同一」と書いているが、zlib の実装差で、圧縮した PNG は環境をまたぐと保証できない。無圧縮（`stored`）なら全環境で保証できる |
| 3 | **PixelOE を任意にした** | 任意の extra（§2.3.2、§11.4） | ブリーフは「変換パイプラインの主役」としている。PyTorch の重さと決定性を理由に既定から外した。グリッドのない入力（`photo`）の品質は、自前の `kcentroid` の出来に左右される |
| 4 | `aseprite` パッケージの成熟度 | アダプタで隔離、代替は自前実装（§5.9、R-01） | Z インデックス、セル拡張、旧形式などへの対応が未確認。自前実装への切り替えを M5 のどの時点で決めるか |
| 5 | グリッド検出の実力としきい値 | 手順と暫定値、較正手順（§11.3、§11.9） | 生成画像は多様で、ヒューリスティックの調整に時間がかかる。較正コーパスの (d)（各バックエンドの生成画像）を誰がどう用意するか |
| 6 | 実機確認待ちの仮定 | タイルの反転順（D-34）、グループの不透明度（D-33）、シート JSON の互換形式（付録 D） | M0 の結果で仕様が変わりうる。M7 と M5 の着手前に確定させたい |
| 7 | セルの正規化 | 透明な縁を削り、空セルを消す（§5.6.4） | 空セルが `.aseprite` との往復で失われる。リンクセルの持ち主の引き継ぎと組み合わさると実装が込み入る |
| 8 | GUI の描画の遅延と二重実装 | サーバが合成、クライアントは描きかけの線だけ仮描画（§14.6） | 大きめのキャンバスで操作感が悪ければ、クライアント側の合成がほしくなる。ラスタライズの TypeScript 実装を Python と一致させ続ける手間 |
| 9 | ツールが 78 個 | `minimal` プロファイル（§10.1.2） | エージェントのコンテキストを圧迫する。個別ツールと `apply_ops` のどちらを主にするか、実地で調整が要る |
| 10 | Windows でのロックと原子的な置き換え | やり直しと `E_IO`（R-10） | GUI サーバやウイルス対策ソフトがファイルを開いていると、置き換えが失敗する |
| 11 | 「validate 全項目パス」の意味 | エラー 0 件が条件。警告は 1 件ずつ判断して報告（§13.7）。孤立ピクセルのしきい値は既定で未設定 | 既定を厳しくすると、意図した 1 ピクセルの表現（目の光など）で詰まる。緩いと検出が形だけになる |
| 12 | `add_layer` などの `if_exists` の既定が `"error"` | §10.8、§10.9 | 冪等にしたいエージェントは `"reuse"` を毎回書く必要がある。既定を `"reuse"` にする案もある |
| 13 | 固定小数点 Oklab の規範データ | 表をリポジトリに置き、ハッシュで固定（付録 B） | 表の生成、Python と TypeScript の一致、並べ替えの「色相」の整数での定義が細かい |
| 14 | 履歴のスナップショット | 直近 200 件、256 MB（§6.3） | 大きなプロジェクトでディスクと時間を使う。差分方式に変えたくなる可能性 |
| 15 | GIF を全フレーム全面で書く | 最適化なし（§8.6.3） | ファイルが大きくなる。差分最適化は v1.x |
| 16 | テーマ: 水色を文字に使えない | 文字は濃紺、水色は線と面（§14.3.3） | 白地に水色の文字はコントラスト不足。「水色基調」は配線と面で表現することになる |
| 17 | テーマ 3 案を、止まらずにオーケストレーターが選ぶ | §14.3.4 | 発注者が選びたい場合は、M8 の最初に声をかけてほしい。3 案は残すので後から差し替えられる |
| 18 | クリーンルームと実装モデルの記憶 | 仕様にアルゴリズムを書き、指示で禁じ、レビューで見る（R-06） | モデルが学習時に見たコードを再現していないことを、完全には証明できない |
| 19 | Python 3.12 以上に限定 | `aseprite` パッケージの要件（D-23） | 3.10 / 3.11 の利用者を切り捨てる |
| 20 | 16 進文字列の JSON の大きさ | 上限を固定（§5.11） | 大きなキャンバスと長いアニメーションで `project.json` が数十 MB になる |
