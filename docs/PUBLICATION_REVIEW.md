## 1. R2-01 — CLI の出力が経路の保護を通らない

**判定: 解消。**

### 1.1 再現が潰れているか

リポジトリの外の一時ディレクトリで、8×8 のプロジェクトに原画を 1 枚 `source add` で登録し、`docs/REVIEW_2.md` R2-01 の 4 つをそのまま実行した［実行］。

| `render --scale 2 --out q.csprite/source/SRC1/original_0000.png` | `ok: true`、原画が変わる | `E_PATH_NOT_ALLOWED`、`reason: protected_project_file`、終了コード 4 |
| `preview --out q.csprite/.cybersprite/history/journal.jsonl` | `ok: true`、以後は編集できない | 同上 |

- 拒否の前後で、プロジェクトの全ファイル（ロックとプレビューを除く）の SHA-256 が一致した。その後の `set_pixel`、`undo`、`validate` は成功した。
- 同じ宛先への `export image --overwrite` は、同じコードと理由で拒否された。境界がそろっている。
- `diff --out`、`schema --out`、`convert` の出力と `--stages` も、`source/` と `.cybersprite/` への宛先を拒否した。
- 保護されていない通常のファイル（`check.png` への 2 回の `render`、`prev/p.png`）は、従来どおり書けた。手順書の使い方は壊れていない。

実装は、CLI の 5 つの出力が `cli/output.py` の `protect_project_output` を経て、書き出しと同じ `formats.common.guard_output` を呼ぶ形である［読解］。複数のファイルを書く経路（`preview` の複数コマ、`schema all`、`convert`）は、全部の宛先を検査してから書く。GUI の、書き出し以外の Op の出力検査（`server/app.py` の `check_outputs`）も、同じ予約領域の検査を呼んでいる［読解。GUI からの実行はしていない］。

### 1.2 テストは十分か

- `tests/unit/test_publication_r2_01.py` の 25 件は、R2-01 の 4 つの再現を含む。3 コマンド × 6 宛先（大文字小文字の別名、`..` を含む）、作業ディレクトリの外、ディレクトリ宛て、ハードリンク、`convert` の 3 種の出力、通常の出力が書けることを確かめている［読解］。

R2-01 が求めた範囲に対して、試験は十分である。

### 1.3 残り — PR-05（minor、公開の後でよい）

**選んでいない別のプロジェクトのファイルへのハードリンクを、プロジェクトの外に置いて宛先にすると、書き込みがリンクを通る**［実行］。

- 再現: プロジェクト V の原画・ジャーナル・`project.json` へのハードリンクを、作業ディレクトリの直下に作る。`-p other.csprite render --out <リンク>`、`-p other.csprite preview --out <リンク>`、`schema project --out <リンクを含むディレクトリ>` は `ok: true` を返し、V の原画、ジャーナル、`project.json` が書き換わった。V は以後 `E_INVALID_PROJECT` になる。
- 原因: ハードリンクの検査は、選んだプロジェクトと、宛先の親にあるプロジェクトだけを調べる。CLI のこの 3 経路は、素の `write_bytes` で書くので、リンク先の中身が変わる。`export image` と `convert` は、一時ファイルを作って置き換えるので、同じ宛先でもリンクが切れるだけで、V は変わらなかった（`convert` は検査を通ってしまうが、実害は無い）。
- 重さ: R2-01 は「自然な宛先で、成功を返してプロジェクトが使えなくなる」問題だった。こちらは、人かエージェントが先にハードリンクを作らないと起きない。公開は止めない。
- 期待する状態: CLI の出力も、書き出しと同じ「一時ファイル → 置き換え」で書く（`core.history.atomic_write`）。どのプロジェクトへのリンクでも、書き込みがリンクを通らなくなる。修正報告の「ハードリンクを含む」は、選んだプロジェクトと親のプロジェクトについては正しい。範囲を `docs/CLI.md` に 1 文で書くとよい。
