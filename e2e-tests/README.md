# e2e-tests/ — 制作テスト

CyberSprite を実際に使って絵を作り、道具と手順書が回るかを確かめる記録である。工学の通しテスト（`tests/e2e/`、`docs/SPEC.md` §13.6）とは別のもの。

## 1. 合否の決め方

- **機械の検査だけでは、合格にならない。** `validate` が `ok: true`、書き出しが `verified: true` でも、見た目の質は保証されない。80×80 の試作は、機械の検査をすべて通したのに、発注者の評価は不合格だった（`docs/REVIEW_1.md` §2.2、R1-02）。
- 1 つのテストの合否は、**人間の判定**で決まる。値は `pending`（未判定）/ `pass` / `fail`。作り手（エージェント）は `pending` のまま渡す。
- 機械の検査が通らないものは、人間の判定の前に差し戻す（`fail` の前の段階）。

## 2. 各テストが残すもの

各テストのディレクトリ（`e2e-tests/<nn>-<名前>/`）に、[`../skills/templates/review-record.md`](../skills/templates/review-record.md) を写した `REVIEW.md` を置く。中身:

1. 題材、プラットフォーム（または決めた制約）、手順書（`skills/workflows/`）。
2. 関門 3 つ（設計 / ブロッキング / 仕上げ前）のレビューシートのパスと、受けた判断。
3. 作り手が疑っている箇所を 3 つ。
4. 機械の検査の結果（`AGENTS.md` §6.3 の条件）と、制約との照合の表。
5. 道具への意見（使い心地の点数はここだけ）。
6. **人間の判定**（`pending` / `pass` / `fail`、判定した人、日付、コメント）。

- レビューシートは `review/` に置いてよい。ただし**参照（他人の絵）を並べたシートは置かない**。それは `.cybersprite/previews/` か `_private/` の中に残し、パスだけを書く（`docs/SPEC.md` §3.6）。
- 従来の `REPORT.md`（作業の経過と道具の摩擦）は、あってよい。判定は `REVIEW.md` に書く。

## 3. 定期の制作テスト

- 大きなスプライト（DS 級 80×80 / 96×96）は、`skills/workflows/turnaround-parts.md` で作る。§3.4 の道 A（原画を見ながら手で打つ）と道 B（ピクセルアート風の三面図を取り込んで直す）の**両方**を作り、発注者が見比べて決める。どちらが良いかは、まだ分かっていない。
- 小さなもの、極小のもの、タイル、場面も、それぞれの手順書で回す。
