# e2e テスト #04 — タイルセット（meadow）報告

- 担当: Claude Opus 5.5（effort 中）／2026-11-12。出力先: `e2e-tests/04-tileset/`
- （サブエージェントの環境では REPORT.md を書き込めなかったため、本文はオーケストレーターが保存した。）

## 1. 作ったもの
- 192×128、1 フレームのオリジナル草原マップ `meadow.csprite`。タイルは 16×16。パレットは自作の 22 色（`new --palette` で明示）。
- タイルセット TS1（空タイル 0 ＋ 16 枚）: 1–3 草（基本、草むら、小花）、4–5 土、6–8 道の縁・外角・内角、9–10 水、11–13 岸の縁・外角・内角、14 花の群れ、15 岩、16 茂み（14–16 は背景透明）。
- 縁と角は 1 方向だけ描き、反転で使い回した（縁: 上 `""`、下 `y`、左 `d`、右 `xd`。外角・内角: `""` / `x` / `y` / `xy`）。
- レイヤーは `ground`（タイルマップ、12×8 全面）と `props`（同じ TS1。茂み 3、岩 3、花 5。花のうち 2 つは `x` 反転）。
- 地形は 13×9 の頂点格子から、角 4 点の組み合わせでタイルと反転を自動で決めた。反転の使用数: なし 87、`y` 12、`x` 3、`xd` 3、`d` 2。

## 2. 作業ログの要約
- `new` 1 回、トランザクション 15 回（`apply` 12、`op` 3）、`undo` 5 回（計 6 段）。実行した Op は 67 個、最終的に残ったのは 40 個。rows（sym 形式）はスクリプトで作り、ピクセルはすべて CyberSprite の Op が書いた。
- **タイル 1 枚の修正が全配置に波及するか**: 水タイル 9 の差は 11 px、配置は 14 か所。`pixels_changed` は 154（= 11×14）。`diff --from 4 --to 5` でも 14 か所すべてが強調された。
- **継ぎ目の確認**: ×3・×4 の全体と拡大、一時レイヤーで中央タイルの 2×2、縁の上下ペア、外角・内角の 4 向き、`d` / `xd` の縦の帯を並べた。不整合なし。
- **`tileset_from_layer`**: 1 回目は上端に透明な行があり、セルが y=1 に詰められて格子の原点が (0,1) にずれ、全タイルが 1 px ずれた（問題 1）。原点を合わせた 2 回目は、重複の統合も反転の照合も正確で、変換の前後で描画は完全に一致した。

## 5. ツールの問題点（重い順）
1. **不具合**: `tileset_from_layer` が、詰めた後のセルの位置を格子の原点にする。警告なしに 1 px ずれ、反転の照合も失敗する。SPEC §5.3.1 では `canvas.grid` がタイルマップ化の既定。
2. タイルセットを削除する Op がない（undo でしか消せず、`.aseprite` にも残る）。
3. `preview --frames all` が `E_INVALID_ARGS`（#03 から未修正。FIX-2 で対応中）。
4. タイルセットを見るプレビューがない（`set_tile_pixels` の結果の `preview.paths` が空）。
5. `set_tile_pixels` の `changed.layers` が空（タイルマップレイヤーの見た目は変わっている）。隠れたレイヤーへの描画では `changed.frames` が空。
6. `tileset_from_layer` の `result.tiles` が空タイル 0 を含む数になっている。
7. タイルセット JSON に、タイルの大きさ、タイルセット名、`base_index`、画像の大きさがなく、`index` がデータ上の番号か表示番号かも書かれていない。`.json` にも width / height / pixel_sha256 が付く（#03 と同じ。FIX-2 で対応中）。
8. `ops describe transform_region` に、反転 → 回転の適用順が書かれていない（タイルの d→x→y と取り違えやすい）。
9. 細かい点: `get_tiles` の CLI サブコマンドがない（`op get_tiles` は動く）。`--grid` を ×4 で使うと絵が白っぽくなる。空のタイルセットを作ると `colors_used` が 1 になる。

良かった点: 反転の描画が正確で自前の合成と完全一致。`set_tiles` の行の書き方が簡潔。タイルの修正が全配置に正しく波及し、`pixels_changed` と `diff` で確かめられた。格子が合っていれば `tileset_from_layer` は正確。`.aseprite` は反転フラグまで一致。多段 undo が予測どおり。

## 6. 評価
4 / 5。タイルの中核は正確で扱いやすい。減点は `tileset_from_layer` の格子のずれと、タイルセットを見る・消す手段がないこと。
