## 1. 作ったもの
- 32×32、右向きのオリジナルキャラクター。赤いキャップ、ティールのジャケット、紺のパンツ、白いスニーカー。
- フレーム 0–7 は歩行（接地・沈み込み・パッシング・伸び上がりを左右で 2 回）。フレーム 8–9 は待機で、呼吸に合わせて 1px 沈む。
- タグは `walk`（0–7、forward、repeat 0）と `idle`（8–9、pingpong）。
- 表示時間: 接地（0, 4）120ms、沈み込み・伸び上がり（1, 3, 5, 7）90ms、パッシング（2, 6）100ms（1 周 800ms）、待機（8, 9）450ms。
- パレットは自作の 18 色（透明 0 を含む）。`new --palette '[...]'` で明示した。
- レイヤーは下から shadow / far_arm / far_leg / body / near_leg / near_arm。
- リンクセル: shadow はフレーム 0 のセルを 1–9 にリンク。body は上下動を 3 つのセルで表した（0 を 2, 4, 6, 8 に、1px 下げた 1 を 5, 9 に、1px 上げた 3 を 7 にリンク）。
- 動きの原則として、4 段の歩行、頭の上下動（0 / +1 / 0 / −1）、脚と逆位相の腕振りを入れた。踏んでいる足は毎フレーム 2px ずつ一定の速さで後ろへ動く（その場歩き）。
- 1 回目は手前と奥の脚で腰の位置が 1px ずれ、歩幅が 10px と 6px で揃わなかった。`undo` で戻し、描き直した。

## 2. 作業ログの要約
- `new` 1 回、トランザクション 16 回（`apply` 15、`op` 1）、`undo --steps 4` 1 回。実行した Op は計 305 個（うち 140 個は undo で取り消し、最終 165 個）。
- 脚と腕は、各フレームで stroke（brush 2）で関節を結ぶ → 靴を draw_rows → outline（外側、4 近傍）→ 腰より上にはみ出た輪郭を erase(rect) の手順で描いた。Op の引数 JSON は `work/limbs.py` で関節座標から作った。ピクセルはすべて CyberSprite の Op が書いた。
- 変更のたびに検証デルタを読み、プレビューを見た（横並べ、`--onion 1,1`、背景色付きの拡大）。最後の変更（revision 17）の後に全 10 フレームを見た。

## 5. ツールの問題点（重い順）
1. `preview` / `render_preview` の frames が、ヘルプと `ops describe` の説明に反して `all`、範囲（`0-9`）、`tag:walk` を受け付けない（`E_INVALID_ARGS`）。同じ指定は `validate` と `link_cel` では動く。
2. `preview` は 8 フレームまでで（10 フレームで `E_LIMIT_EXCEEDED`、理由は details に埋もれる）、フレームを横に並べた 1 枚の画像を作る手段がない。
3. `preview --background '#ffffff'` が `E_COLOR_NOT_IN_PALETTE`。診断用のプレビューの下地はパレット外の色でもよいはず（番号 12 で回避）。
4. オニオンスキンが既定の市松模様の上でほとんど見えず、前後の区別もつきにくい。タグの中でループ（フレーム 0 の前 = 7）しない。
5. `info --include layers` にリンク元が出ない（`link_cel --dry-run` で確認した）。
6. 書き出し結果で、画像でないファイル（シートの .json、.gpl）にも width / height / pixel_sha256 が付く。
7. 細かい点: `--out` のファイル名書式（`{frame:02}` など）が `export --help` にない。タグの既定色 `#19c3e6` がパレットにない（引数の説明は「パレットの色」）。GPL 書き出しで透明番号が `0 0 0` になり、警告がない。1 回のトランザクションで複数のリンク組を編集すると、`changed.linked_frames` が組ごとでなく 1 つの列にまとまる。

良かった点: トランザクション、検証デルタ、`undo --steps` が分かりやすく確実。stroke・outline・erase の組み合わせで関節座標から手足を安定して描けた。`link_cel` の範囲指定。書き出しの自己検査。.aseprite はリンク構造まで読み戻して一致。
